# Документы с привязкой к контексту (document_refs)

## Цель

Хранить все созданные документы (файлы) с привязками к контексту создания и автором, чтобы:
- показывать в UI селект со всеми подходящими документами при выборе значения интерактивного свойства «Документ»;
- фильтровать документы по типу, нотации, компоненту, модели, ноде.

## Текущее состояние

- Таблица **files**: метаданные файла (id, owner_id, filename, content_type, size, object_key, created_at). Контекст создания не хранится.
- Фронт создаёт документ через `POST /api/v1/files/upload-markdown`, получает `file_id`, сохраняет его в attrs модели/узла/диаграммы или в `componentProperties` узла. Список документов для селекта сейчас собирается на фронте из уже использованных в модели file_id (узлы, диаграммы, значения свойств).

## Предлагаемая модель

### Новая таблица `document_refs`

Связывает файл с контекстом «где документ создан/привязан» и автором. Один файл может иметь несколько записей в разных контекстах (один и тот же документ привязан к модели и к компоненту).

| Колонка          | Тип      | Описание |
|------------------|----------|----------|
| id               | uuid PK  | Идентификатор записи |
| file_id          | uuid FK→files | Файл (документ) |
| created_by       | uuid FK→users | Автор (кто создал/привязал) |
| created_at       | timestamp | Время создания привязки |
| **Контекст (все nullable):** | | |
| node_type_id     | uuid FK→node_types | Тип узла (если документ в контексте типа узла) |
| link_type_id     | uuid FK→link_types | Тип связи (если в контексте типа связи) |
| notation_id      | uuid FK→notations | Нотация |
| component_id     | uuid FK→components | Компонент нотации |
| model_id         | uuid FK→models | Модель |
| node_id          | uuid FK→nodes | Конкретный узел в дереве модели |

Ограничение: хотя бы одно из полей контекста (node_type_id, link_type_id, notation_id, component_id, model_id, node_id) должно быть задано, иначе привязка «ни о чём».

### Сценарии заполнения

1. **«Новый документ» в редакторе модели** (интерактивное свойство компонента на узле): после создания файла вызываем API регистрации привязки с `file_id`, `model_id`, `node_id`, `notation_id`, `component_id` (и `created_by` = текущий пользователь).
2. **Документация узла** (вкладка «Документация» у узла): при первом сохранении документа можно зарегистрировать привязку с `model_id`, `node_id`.
3. **Документация диаграммы/модели**: привязка с `model_id` (и при необходимости diagram_id, если появится отдельная сущность диаграммы в БД).

Таким образом, при открытии селекта «Выберите документ» в редакторе модели можно запросить, например:
- документы по модели: `GET /api/v1/documents?model_id=...`;
- документы по компоненту: `?component_id=...`;
- документы по нотации: `?notation_id=...`;
- «все мои документы»: без фильтров, но только созданные текущим пользователем или с доступом.

## API (реализовано)

- **POST /api/v1/documents** — зарегистрировать привязку документа к контексту. Body (camelCase): `fileId` (обязательный), опционально `modelId`, `notationId`, `componentId`, `nodeId`, `nodeTypeId`, `linkTypeId`, `diagramId`, `relationId`, `nodeShapeId`. Проверка прав на файл и на сущности контекста. Ответ: `{ fileId, label }`.
- **GET /api/v1/documents** — список документов для селекта (только созданные текущим пользователем). Query-параметры (camelCase, опциональные): `modelId`, `notationId`, `componentId`, `nodeId`, `nodeTypeId`, `linkTypeId`, `diagramId`, `relationId`, `nodeShapeId`. Ответ: массив `{ fileId, label }` (label = filename файла).

При необходимости можно добавить в таблицу поле `title` (nullable) для отображаемого названия документа в селекте, по умолчанию использовать `files.filename`.

## Подразделение для селекта

На фронте селект можно фильтровать по уровню:
- **По модели** — документы, привязанные к этой модели (и к её узлам).
- **По нотации** — документы, привязанные к нотации или к её компонентам.
- **По компоненту** — документы, созданные в контексте этого компонента (например, интерактивное свойство этого компонента).
- **По типу узла/связи** — документы, привязанные к типу (если в будущем будет контекст «документация типа»).
- **По ноде** — документы, привязанные к конкретному узлу модели.

Имеет смысл по умолчанию в панели свойств узла показывать документы для текущей модели + текущего компонента, с возможностью расширить до «все мои документы».

## Миграция и обратная совместимость

- Существующие файлы не имеют записей в `document_refs`. Селект на фронте может по-прежнему объединять: (1) документы из API `GET /documents?...` и (2) документы, уже подставленные в модели (из attrs и componentProperties), чтобы старые данные продолжали отображаться и быть выбираемыми.
- При следующем сохранении документа в контексте (например, при создании через «Новый документ») бэкенд создаёт запись в `document_refs`; опционально можно добавить фоновую задачу или скрипт, который по существующим ссылкам в attrs создаёт записи `document_refs` постфактум.
